# GitHub-контент-бот для Telegram-канала

Реализация ТЗ: бот отслеживает GitHub-репозитории (свои — через webhook,
чужие/трендовые — через периодический опрос REST API), генерирует лонгпосты
через Gemini API, присылает их автору на согласование инлайн-кнопками,
считает вовлечённость и раз в неделю присылает отчёт с рекомендациями.

## Структура проекта

```
config.py            конфигурация из переменных окружения
database.py          SQLite (aiosqlite): tracked_repos, posts, metrics
text_utils.py         экранирование HTML, парсинг ссылок на репозитории
telegram_utils.py     safe_send_message — устойчивость к 429 Too Many Requests
github_service.py     GitHub REST API: README/релизы/коммиты, проверка подписи webhook
gemini_service.py     генерация постов и еженедельных рекомендаций через Gemini
keyboards.py          инлайн-клавиатуры черновика и опубликованного поста
states.py             FSM-состояния для ручной правки/перегенерации
pipeline.py           общий пайплайн: GitHub -> Gemini -> черновик -> отправка админу
handlers.py           команды, колбэки кнопок, сбор реакций/комментариев
analytics_service.py  расчёт ERR, топ проектов, текст еженедельного отчёта
scheduler_jobs.py     APScheduler: опрос репозиториев + отчёт по воскресеньям
webhook_server.py     aiohttp: приём GitHub webhook + редирект-трекер кликов
main.py               точка входа
```

## Установка

```bash
python3.11 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp ..env .env
# заполните .env своими значениями (см. комментарии в файле)
python main.py
```

## Настройка Telegram

1. Создайте бота через **@BotFather**, получите `BOT_TOKEN`.
2. Узнайте свой numeric id (например, у @userinfobot) — впишите в `ADMIN_IDS`
   (через запятую, если админов несколько).
3. Добавьте бота **администратором канала** с правом публикации сообщений,
   получите `CHANNEL_ID` (обычно вида `-100xxxxxxxxxx`).
4. Чтобы бот умел считать реакции на постах, у него должны быть права
   администратора канала — Telegram присылает событие
   `message_reaction_count` только ботам-админам.

## Настройка GitHub

1. **Личные проекты** (свои репозитории): в репозитории →
   *Settings → Webhooks → Add webhook*:
   - Payload URL: `{PUBLIC_BASE_URL}/webhook/github`
   - Content type: `application/json`
   - Secret: значение из `GITHUB_WEBHOOK_SECRET`
   - События: отметьте *Releases* и *Pushes* (не берите "Send me everything" —
     будет шумно).
   - `PUBLIC_BASE_URL` должен быть реальным HTTPS-адресом, за которым виден
     ваш сервер (домен + reverse-proxy, либо туннель типа Cloudflare
     Tunnel/ngrok на время тестов).

2. **Сторонние/трендовые проекты**: перечислите их в `TRACKED_REPOS`
   (`owner/repo1,owner/repo2`) — бот будет опрашивать GitHub REST API раз в
   `POLL_INTERVAL_MINUTES` минут и сравнивать последний релиз/коммит с тем,
   что видел раньше.

3. Заведите **Personal Access Token** (`GITHUB_TOKEN`) — без него анонимные
   запросы к GitHub REST API упираются в лимит 60 запросов в час, с токеном
   — 5000/час.

## Команды бота (только для `ADMIN_IDS`)

- `/add_repo <ссылка или owner/repo>` — вручную сгенерировать пост по
  конкретному репозиторию.
- `/stats` — быстрая статистика за последние 7 дней.
- `/top_projects` — топ-10 постов по ERR за всё время.

## Черновики и согласование

Бот **никогда не публикует в канал напрямую**. По каждому новому событию
(релиз, пуш, ручной `/add_repo`) он присылает админу(ам) черновик с кнопками:

- 🚀 **Опубликовать** — отправляет пост в канал как есть.
- 🔄 **Перегенерировать** — бот спросит уточнение и попросит Gemini
  переписать пост (можно отправить `-`, чтобы просто получить другой вариант).
- ✏️ **Редактировать** — пришлите новый текст целиком, HTML-разметка Telegram
  поддерживается.
- ❌ **Отклонить** — черновик помечается отклонённым и больше не предлагается.

## Расчёт ERR (эффективной вовлечённости)

`ERR = клики_GitHub·1.0 + клики_Обсудить·1.5 + комментарии·3.0 + реакции·1.0 + репосты·4.0`

Веса заданы в `config.ERR_WEIGHTS` — подстройте под свою аудиторию.
Клики по кнопке GitHub считаются через собственный редирект
(`/r/<post_id>/github`), реакции приходят от Telegram автоматически.

### Подсчёт комментариев

Bot API не даёт «просто счётчик комментариев» под постом канала. Если у
канала есть привязанная группа обсуждений и вы укажете её `DISCUSSION_GROUP_ID`
(бот должен состоять в этой группе), бот попробует best-effort-способ:
считает сообщение комментарием, если это ответ на автоматически пересланную
копию поста канала. Логика зависит от того, как Telegram сейчас передаёт
метаданные пересылки (`forward_origin`/`forward_from_message_id`) — если
после обновления Bot API счётчик перестанет расти, проверьте актуальный
формат в `handlers.py::_extract_forwarded_channel_message_id`.

Репосты (`reposts_count`) на данный момент не собираются автоматически (Bot
API их не отдаёт) — поле в БД зарезервировано на случай, если вы захотите
считать их вручную или через сторонний сервис аналитики; используйте
`database.set_metric_counts(post_id, reposts=...)`.

## Еженедельный отчёт

Каждое воскресенье в 09:00 (таймзона `TIMEZONE`) бот присылает админам:
топ-3 проекта недели, разбивку по тегам с наибольшим откликом и короткие
рекомендации от Gemini на основе этих данных.

## Заметки по надёжности

- Весь текст от Gemini и из README репозиториев экранируется
  (`text_utils.escape_html`) перед сборкой HTML-сообщения — финальный текст
  собирается ботом, а не приходит от Gemini напрямую, поэтому ошибка
  `Can't parse entities` от Telegram практически исключена.
- Отправка сообщений оборачивается в `telegram_utils.safe_send_message`,
  которая ловит `TelegramRetryAfter` (ошибка 429) и повторяет попытку после
  паузы.
- Дедупликация — по паре `repo_full_name + событие` (`dedup_key` с уникальным
  индексом в БД), так что один и тот же релиз/коммит не предлагается дважды.

## Gemini API

Используется пакет `google-genai` (`from google import genai`). SDK
меняется довольно часто — если генерация начнёт падать после обновления
пакета, в первую очередь свяьте это с изменением сигнатуры
`GenerateContentConfig`/`response_schema` и сверьтесь с актуальной
документацией: https://googleapis.github.io/python-genai/. В коде уже есть
защитный `try/except` — при сбое Gemini бот пришлёт черновик-заглушку вместо
падения.

## Переход на PostgreSQL

Схема в `database.py` рассчитана на SQLite (`aiosqlite`), но описана простыми
таблицами без специфичных для SQLite фич. Чтобы перейти на PostgreSQL,
достаточно переписать функции в `database.py` на `asyncpg`/SQLAlchemy —
остальной код обращается к БД только через эти функции.

## Деплой

Для постоянной работы удобно завести systemd unit, который перезапускает
`python main.py` при падении, и выставить `WEBHOOK_PORT` за reverse-proxy
(nginx/Caddy) с HTTPS — GitHub требует https для webhook-адреса.
